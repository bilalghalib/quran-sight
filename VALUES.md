# Quran-Sight: Core Values & Promises

## Our Core Values (Constitutive Attentional Policies)

These are the things we pay attention to that are meaningful to us - not instrumental goals, but what makes this work worth doing:

### 1. MOMENTS when hidden linguistic structures become visible through systematic inquiry

We believe the Quranic text contains patterns that reward patient, rigorous exploration. We pay attention to tools and features that make invisible relationships visible - whether that's morphological families emerging from a single root, distributional patterns across 6,236 verses, or the symbolic resonance of Arabic letters.

### 2. ENCOUNTERS where sacred text remains whole rather than fragmented into data points

We honor the Quran as an integrated revelation, not a database to be mined. We pay attention to whether our tools encourage engagement with complete passages, contextual understanding, and the text's internal coherence - resisting reductionism that treats verses as isolated quotes.

### 3. SPACES where multiple ways of knowing can coexist without hierarchy

We recognize that the Quranic text serves scholarly analysis, spiritual contemplation, linguistic study, artistic inspiration, and personal reflection simultaneously. We pay attention to whether our design choices honor these different modes rather than privileging one over others.

### 4. EXPERIENCES where cultural authenticity shapes technical decisions rather than being an afterthought

We believe Arabic language structure, Islamic scholarly traditions, and spiritual practices should drive architecture, not be adapted to Western design patterns. We pay attention to whether our code honors right-to-left flow, respects theological sensitivities, and implements patterns rooted in Arabic linguistic reality.

### 5. PATTERNS that emerge from exploration rather than being prescribed by interpretation

We value tools that help seekers discover what's there over tools that tell them what it means. We pay attention to whether features enable users to find their own patterns, form their own questions, and follow their own curiosity - providing structure without dictating conclusions.

## Our Core Promises

### What We Commit To

**1. Complete Text Access**
- We will always provide access to all 6,236 verses without arbitrary truncation
- We will load and cache the full Quranic corpus to enable comprehensive exploration
- We will not create paywalls or feature gates that limit access to sacred text

**2. Linguistic Rigor**
- We will implement tri-root extraction and morphological analysis using established Arabic linguistic principles
- We will distinguish between attested and theoretical forms, acknowledging system boundaries
- We will cite our analytical approach and remain transparent about algorithmic limitations
- We will not claim linguistic authority we don't have - theoretical forms are marked, algorithms are documented

**3. Multiple Modes of Engagement**
- We will support both analytical inquiry (search, statistics, morphology) and contemplative practice (reading, meditation, visual patterns)
- We will provide ways to reduce interface complexity for those seeking simplicity
- We will enable export and sharing for scholarly, educational, and artistic use
- We will not force all users through a single prescribed interaction model

**4. Cultural & Spiritual Respect**
- We will honor Islamic scholarly conventions (theoretical forms, letter meanings, etymological interpretations)
- We will use authentic Arabic typography and layout (RTL, proper fonts, diacritic handling)
- We will preserve the text's sacredness in our design choices (no decontextualization, no trivial gamification)
- We will acknowledge when features blend spiritual traditions (e.g., Sufi letter meanings vs. scholarly consensus)

**5. Open Exploration**
- We will enable user-driven search and discovery without prescribing what's "important"
- We will show distributional patterns, morphological families, and linguistic structures without imposing interpretive frameworks
- We will provide context (verse numbers, surrounding text, usage examples) without inserting theological commentary
- We will let the text speak through patterns rather than telling users what to see

**6. Technical Excellence in Service of Values**
- We will optimize performance to enable comprehensive analysis (caching, efficient algorithms)
- We will write clear, documented code that others can learn from and adapt
- We will make deliberate architectural choices that serve user values over technical fashion
- We will not sacrifice accuracy, completeness, or cultural authenticity for convenience

## Our Core "Must Nots"

### What We Will Not Do

**1. Must Not Fragment or Excerpt Arbitrarily**
- ❌ No "Verse of the Day" features that decontextualize
- ❌ No sampling or truncation that breaks textual integrity
- ❌ No presenting verses without surrounding context available
- ✓ Instead: Full text always accessible, context shown with search results, verse boundaries respected but not isolated

**2. Must Not Prescribe Interpretation**
- ❌ No theological commentary presented as fact
- ❌ No "This verse means..." authoritative explanations
- ❌ No guided paths that channel users toward predetermined insights
- ✓ Instead: Show linguistic patterns, etymologies, usage statistics; let users form their own understanding

**3. Must Not Appropriate Without Honoring Tradition**
- ❌ No treating Islamic concepts as exotic aesthetics
- ❌ No ignoring Arabic linguistic structure in favor of Western UX patterns
- ❌ No spiritual practices (letter meanings, numerology) presented without acknowledging their traditional contexts
- ✓ Instead: RTL-first design, Islamic scholarly conventions, cultural context provided

**4. Must Not Create Barriers Between Seekers and Text**
- ❌ No authentication requirements for basic text access
- ❌ No paywalls for search or analysis features
- ❌ No complexity that excludes non-technical users
- ✓ Instead: Direct access, progressive disclosure of complexity, multiple entry points

**5. Must Not Sacrifice Accuracy for Simplicity**
- ❌ No hiding theoretical forms just because they're complicated
- ❌ No oversimplifying morphological patterns for "ease of use"
- ❌ No removing scholarly rigor to make UI cleaner
- ✓ Instead: Provide both simple and advanced modes, explain complexity, maintain accuracy while offering layers

**6. Must Not Reduce Sacred Text to Data**
- ❌ No purely quantitative approaches that lose the text's spiritual dimension
- ❌ No visualization that makes the Quran a dataset rather than revelation
- ❌ No features that treat words as tokens rather than carrying meaning
- ✓ Instead: Balance analytical tools with contemplative affordances, honor both intellectual and spiritual inquiry

**7. Must Not Lock Value in Code**
- ❌ No keeping sophisticated features (spiral visualization) inaccessible in deployed app
- ❌ No building capabilities users need but can't reach
- ❌ No prioritizing technical elegance over user value delivery
- ✓ Instead: Deploy what we build, make affordances accessible, serve real user values

## Decision Framework: "Hell Yes or No"

When evaluating any feature, change, or direction, ask:

### Does this serve our core values?

1. **Does it make hidden patterns visible?** (Value #1)
2. **Does it honor text wholeness?** (Value #2)
3. **Does it support multiple ways of knowing?** (Value #3)
4. **Does it embody cultural authenticity?** (Value #4)
5. **Does it enable discovery over prescription?** (Value #5)

### Does it keep our promises?

- Complete text access? ✓
- Linguistic rigor? ✓
- Multiple engagement modes? ✓
- Cultural respect? ✓
- Open exploration? ✓
- Technical excellence serving values? ✓

### Does it avoid our "must nots"?

- No fragmentation? ✓
- No prescribed interpretation? ✓
- No appropriation? ✓
- No barriers? ✓
- No sacrificing accuracy? ✓
- No reducing text to data? ✓
- No locking value in code? ✓

## If the answer to all three is "HELL YES" → Do it.

## If any answer is lukewarm or no → Don't do it.

This framework helps us:
- Say yes to things that deeply serve our mission
- Say no to feature creep that dilutes our focus
- Make decisive choices based on values rather than opinions
- Maintain coherence as the project evolves

### The Test

For any proposed change, we ask: **"Is this a HELL YES for serving our values?"**

Not "would it be nice" or "users might like it" or "it's technically interesting" - but **"Does this deeply serve what we stand for?"**

That clarity makes decisions obvious.
